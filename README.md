# 6-DOF Industrial Manipulator: PG-SAC Code Bundle

This bundle refactors the supplied Python snippets into separate modules for the PyBullet environment, SAC training, continued training, Optuna reward-weight tuning, diagnostics, and plotting.

## Files and purpose

| File | Purpose |
|---|---|
| `src/env/arm_env.py` | Gymnasium environment with six actuated joints, a position-held seventh KUKA iiwa joint, energy history, tracking, energy, and jerk metrics. |
| `src/training/callbacks.py` | Records per-episode reward, tracking error, energy estimate, jerk, and success to CSV. |
| `src/training/train_pg_sac.py` | Trains a Stable-Baselines3 SAC model and saves the checkpoint. |
| `src/training/continue_training.py` | Loads a saved SAC checkpoint and continues training, corresponding to the extra training-round snippet. |
| `src/simulation/run_pybullet_diagnostics.py` | Runs a standalone PyBullet position-control diagnostic and writes measured metrics to CSV. |
| `src/optimization/optuna_reward_tuning.py` | Runs reward-weight search by training a new SAC model for each Optuna trial. This is compute-intensive. |
| `src/analysis/plot_training_results.py` | Plots metrics from real CSV logs generated by the training/diagnostic scripts. |
| `src/analysis/plot_synthetic_demo_curves.py` | Creates illustrative synthetic energy and jerk curves for testing plot styles only. Do not report these as measured results. |

## Setup

Use Python 3.10 or newer. From the repository root:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\\Scripts\\Activate.ps1
# macOS/Linux:
source .venv/bin/activate

python -m pip install --upgrade pip
pip install -r requirements.txt
```

Install a PyTorch build compatible with your machine and CUDA version using the official PyTorch installation selector if needed.

## Run the training script

```bash
python -m src.training.train_pg_sac --timesteps 100000 --device auto --check-env
```

The script saves a model under `models/pg_sac_final.zip` and episode metrics in `logs/training_log.csv`.

## Continue a saved model

```bash
python -m src.training.continue_training --model models/pg_sac_final.zip --timesteps 100000
```

## Run a PyBullet diagnostic

```bash
python -m src.simulation.run_pybullet_diagnostics --steps 1000
```

Add `--gui` to display PyBullet's GUI. Output is written to `results/simulation_metrics.csv`.

## Tune reward weights

```bash
python -m src.optimization.optuna_reward_tuning --trials 50 --train-timesteps 10000 --eval-episodes 3
```

This trains a fresh policy for each trial and can take a long time. For publication-grade reproduction, match the exact manuscript environment, reward scaling, seed protocol, trial budget, and stopping rule.

## Generate figures

After creating CSV logs:

```bash
python -m src.analysis.plot_training_results
```

For illustrative plots only:

```bash
python -m src.analysis.plot_synthetic_demo_curves
```

Files saved under `results/demo_figures/` are explicitly synthetic, not experimental data.

## Research reproducibility notes

The supplied snippets contain a mixture of environment-driven measurements and plots constructed using random/synthetic values. The `plot_training_results.py` script only plots CSV values produced by simulations/training. The training callback starts a fresh CSV for a new run; continued training appends to its own log with continuous episode numbering. `plot_synthetic_demo_curves.py` is deliberately named and saved as demo-only output so it is not confused with experimental results.

The original plotting code's energy baseline and torque profiles use random values, and its reward convergence graph uses a hand-crafted curve; those are illustrative rather than measured model comparisons. The diagnostic script calculates a mechanical energy estimate from simulated joint torque and velocity. This quantity is not a calibrated measurement of electrical energy consumed by a physical robot. Optuna reports success as a fraction of successful evaluation episodes (not a fraction of individual timesteps).

The KUKA iiwa URDF supplied with PyBullet has seven revolute joints. The provided training environment actuates joints 0–5 and actively position-holds joint 6 at zero to emulate a six-actuated-joint setup. This is not identical to a purpose-built six-DOF robot URDF. The observation includes a scalar mean of the most recent energy samples (up to 10), rather than the full historical energy vector described in the manuscript. The current environment also does not implement a separate collision-penalty term from the paper’s conceptual reward formulation; joint target angles are clipped to the configured limits. This starter bundle does not implement a separate sequential multi-target benchmark. Episode success is counted consistently with the configured 20 mm termination tolerance.

The environment default reward weights are set to the manuscript-reported rounded values `(0.570, 0.173, 0.258)`. The Optuna script derives the jerk weight as `1 - w1 - w2` for each trial. This refactored pipeline still does not exactly reproduce the manuscript: the supplied environment uses PyBullet’s seven-joint KUKA iiwa URDF with the seventh joint held at zero, while the manuscript describes a purpose-designed six-DOF URDF. Reconcile robot model, reward scaling, trial count, random seeds, and evaluation protocol before claiming exact reproduction.
